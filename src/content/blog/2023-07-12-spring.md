### Day8_AWS에 프로젝트 배포하기

Amazon Web Service의 elastic beanstock을 이용하여 서버를 구축하고 블로그 서비스를 업로드해보았습니다.

### AWS의 서비스 구성도

![](/images/medium/ae4c236aabbd/1.png)

*출처: [https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/concepts-webserver.html](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/concepts-webserver.html)*

- EC2: 가상의 PC(서버) 1대를 임대하는 서비스
- Auto Scaling Group: 서비스 이용자 증가에 따라 사용자의 요청이 많아지는 경우, 1대의 서버로 처리하기 어렵기 때문에 여러 개의 EC2가 필요하며, Auto Scaling Group에 의해 자동으로(이용자 현황에 따라) EC2를 늘이거나 줄인다.
- Load Balancer: 사용자의 요청 을 분산한다. Load Balancer가 어디로 요청을 분산시킬지 그룹을 정해야 하는데 이 그룹을 Target Group이라고 한다.
- RDS: 데이터 저장소.(DB)

### [Elastic Beanstal에서 RDS 생성]

DB 생성 및 연결 이후 table까지 생성해 주었다.

```
create database blog;

use blog;

DROP TABLE IF EXISTS article;
create table article(
id bigint not null AUTO_INCREMENT,
author varchar(255) not null,
content varchar(255) not null,
created_at timestamp,
title varchar(255) not null,
updated_at timestamp,
primary key (id)
);

DROP TABLE IF EXISTS refresh_token;
create table refresh_token(
id bigint not null AUTO_INCREMENT,
refresh_token varchar(255) not null,
user_id bigint not null,
primary key(id)
);

DROP TABLE IF EXISTS users;
create table users(
id bigint not null AUTO_INCREMENT,
created_at timestamp,
email varchar(255) not null,
nickname varchar(255),
password varchar(255),
updated_at timestamp,
primary key(id)
);
```
