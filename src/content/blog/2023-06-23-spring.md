## IoC(Inversion Of Control) Container

인스턴스 생성~소멸까지 인스턴스 생명주기 관리를 컨테이너가 대신 해준다. 객체 관리의 주체가 프레임워크가 되기 때문에 개발자는 로직에 집중할 수 있다.

POJO(Plain Old Java Object)

특정 자바 모델이나 기능, framework를 따르지 않는 Java Object를 지칭한다. 대표적으로 Java Bean 객체가 있다.

## IOC 분류

- DL(Dependancy Lookup): 저장소에 저장되어있는 Bean에 접근하기 위해 컨테이너가 제공하는 API를 이용하여 Bean을 lookup 하는 것
- **DI(Dependancy Injection):** 각 클래스 간의 의존 관계를 빈 설정(Bean Definition) 정보를 바탕으로 컨테이너가 자동으로 연결해주는 것(필요한 객체를 직접 생성하는 것이 아닌 외부로부터 객체를 받아 사용하는 것)

### DI를 하는 이유

1. TEST가 용이해진다
2. 코드의 재사용성을 높여준다
3. 객체 간의 의존성을 줄이거나 없앨 수 있다.
4. 객체 간의 결합도를 낮추면서 유연한 코드를 작성할 수 있다.

### DI 3가지 방법

— Countructor Injection(생성자 주입)  
— Setter Injection(수정자 주입)  
 — Method Injection(필드 주입)
