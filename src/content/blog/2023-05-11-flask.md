## 쿠키

클라이언트의 브라우저와 웹 서버와의 사이에서 상태를 관리하기 위해 브라우저에 저장된 정보와 그 구조.

```
from flask import request
from flask import make_response, render_template, response

# key를 지정한다.
username = request.cookies.get('username')

#key와 value 설정
response = make_response(render_template("contact.html"))
response.set_cookie("username", "AK")


#쿠키로 부터 값 삭제
response = make_response(render_template("contact.html"))
response.delete_cookie("username", "AK")
```

## 세션

사용자의 로그인 정보 등을 서버에 유지하고, 일련의 처리를 계속적으로 실시할 수 있도록 하는 구조.

1. 사용자가 로그인 조작
2. 서버는 세션 ID를 발행하고 사용자 정보를 연결하여 종보 유지
3. 세션 ID를 브라우저의 쿠키에 저장
4. 이후 요청 시 보내지는 쿠키로부터 세션 ID를 취득하고 연결된 사용자를 취득
5. 취득한 사용자에게 필요한 처리르 하거나 정보 반환.
- stateless: 서버가 클라이언트의 정보를 유지하지 않아 웹 서버 측에서 상태를 관리할 수 없는 것

```
from flask import session

#세션에 값 설정
session['username'] ='AK'
#세션으로부터 값 취득
username=session['username']
#세션으로부터 값 삭제
session.pop('username', None)
```

## 응답

브라우저로부터 온 요청에 대해 서버가 클라이언트에게 반환하는 응답.

- status_code: 응답 상태 코
- headers: 응답 헤더
- set_cookie: 쿠키 설정
- delete_cookie: 쿠키 삭제

```
return render_template('contact_complete.html')
```

```
from flask import request

@myapp.route("/contact")

    # 응답 오브젝트를 반환한다
    return response
```

### CRUD 앱의 모듈 작성

```
def create_app():
    #플라스크 인스턴스 생성
    myapp = Flask(__name__)

    #curd 패키지로부터 views를 import
    from myapps.curd import views as crud_views
    
    #curd 앱 등록
    #url_prefix를 curd로 지정
    #앤드포인트의 모든 url이 curd로부터 시작되게 한다.
    myapp.register_blueprint(crud_views.curd, url_prefix="/curd")

    return myapp
```

### Buleprint

앱을 분할하기 위한 플라스크의 기능. 앱의 규모가 커져도 간결한 상태를 유지할 수 있어 보수성이 향상된다.

[특징]  
- 앱 분할할 수 있다.  
URL 프리픽스 및 서브 도메인을 지정하여 다른 애플리케이션 루트와 구별할 수 있다.  
Blueprint 단위로 템플릿을 나눌 수 있다.  
Blueprint단위로 정적 파일을 나눌 수 있다.

[사용 방법]

1. 객체(blueprint ) 생성
2. 플라스크 앱인 myapp 인스턴스의 register_blueprint 메소드에 전달해 등록

```
#blueprint 객체 생성
sample = Blueprint(
    __name__,
    "sample",
    static_folder = "static",
    template_folder = "templates",
    url_prefix = "/sample",
    subdomain = "example",
)

#생성한 blueprint 객체를 register_blueprint 함수로 등록한다.
myapp.register_blueprint(sample, url_prefix="/sample", subdomain = "example")

#blueprint 객체를 전달한다.(url_preifx는 sample2가 우선이다.)
myapp.register_blueprint(sample, url_prefix="/sample2")
```

- blueprint: 등록하는 blueprint 앱. Blueprint 클래스의 객체를 지정한다.
- url_prefix: Blueprint 앱에서 모든 URL 맨 앞에 추가하는 다른 앱의 경로와 구별하기 위한 경로
- subdomain: Blueprint를 서브 도메인으로서 이용하는 경우에 지정한다.

**[Blueprint로 앱 분할하는 모듈화할 때 고려해야할 것]**

- url 프리픽스 및 서브 도메인으로 나누고 싶은가
- 화면의 레이아웃으로 나우고 싶은가

**[여러 개의 blueprint로 템플릿을 이용할 때 주의할 점]**

```
curd = Blueprint("curd",__name__, template_folder="template")
```

가장 먼저 등록한 blueprint의 템플릿이 다른 blueprint의 템플릿보다 우선되며, 2번째 이후의 blueprint 템플릿을 표시할 수 없게된다.

→ templates 디렉터리와 HTML 파일 사이에 Blueprint로 등록한 앱 이름의 디렉터리를 끼워넣어 방지.

### [프로그래머스 예제]

3x 마을 사람들은 3을 저주의 숫자라고 생각하기 때문에 3의 배수와 숫자 3을 사용하지 않습니다. 3x 마을 사람들의 숫자는 다음과 같습니다.

![](/images/medium/d3a997d3a41b/2.png)

정수 `n`이 매개변수로 주어질 때, `n`을 3x 마을에서 사용하는 숫자로 바꿔 return하도록 solution 함수를 완성해주세요.

제한사항

- 1 ≤ `n` ≤ 100

sol1] 3x 마을의 숫자를 10진수로 변환 가능하나, 그 반대로는 변환이 어려웠다. 다만 n이 100일 때의 3x 마을의 숫자가 185가 나오는 것을 확인할 수 있었다.

```
def solution(n):
    answer = 0
    a = 0
    b = 0
    c = 0

    for i in range(1, n + 1):
        if i % 3 == 0:
            a += 1

    for j in range(1, n + 1):
        if "3" in str(j):
            b += 1

    for k in range(n + 1):
        if k % 3 == 0 and "3" in str(k):
            c += 1

    answer = n - a - b + c

    return answer

print(solution(16))  # 25
print(solution(185))  # 100
```

sol2] 1 ≤ `n` ≤ 100 일 때, 1 ≤ `3x` ≤ 185 임을 확인하여 아래와 같이 코드를 작성했다.

```
def solution2(n):
    a = []
    for j in range(1, 101):
        a.append(j)

    b = []
    for i in range(1, 186):
        if i % 3 != 0 and "3" not in str(i):
            b.append(i)

    a[n - 1] = b[n - 1]

    return a[n - 1]


print(solution2(15))  
print(solution2(40))  
print(solution2(100))  
```

sol3]n 값에 대한 제한 사항이 100 이상의 큰 수가 온다면, 더 효율적인 코드로 작성되어야 할 것 같아, 아래와 같이 코드를 개선해보았다.

```
def solution3(n):
    answer = 0
    for _ in range(n):
        answer += 1

        while answer % 3 == 0 or "3" in str(answer):
            answer += 1

    return answer
```
