### @ComponentScan

사용자가 등록한 빈을 읽고 등록하는 애너테이션 @Component 라는 애너테이션을 가진 클래스를 찾아 빈으로 등록한다.

@Component을 가지고 있는 애너테이션 명과 그 설명

- @**Configuration **/ 설정 파일 등록
- @**Repository **/ ORM 매핑
- @**Controller**, @**RestController **/ 라우터
- @**Service **/ 비지니스 로직

=>모두 @Component을 가지고 있으나. 빈이 무슨 역할을 하는지 구분하기 위해 다른 이름으로 덮어둔 것.

### @EnableAutoConfiguration

자동 구성을 활성화하는 애너테이션. 서버가 실행될 때 스프링 부트의 **메타 파일***을 읽고 정의된 설정들을 자동으로 구성하는 역할을 한다.

### @RestController

**라우터 ***역할을 하는 애너테이션.

### [용어 설명]

- 라우터: HTTP 요청과 메서드를 연결하는 장치. 이 애너테이션이 있어야 요청에 맞는 메서드를 실행할 수 있다.
- 메타 데이터: 데이터에 대한 설명을 담고 있는 데이터

## 스프링 부터의 구조

## - 계층

### 프레젠테이션 계층

HTTP 요청을 받고 이 요청을 비즈니스 계층으로 전송.

/ 컨트롤러(@**Controller**)

### 비즈니스 계층

모든 비즈니스 로직 처리. 서비스를 만들기 위한 로직

### 퍼시스턴스 계층

DB 관련 로직 처리. 이 과정에서 데이터 베이스에 접근하는 **DAO***객체를 사용할 수 도 있다.

### [용어 설명]

DAO: DB계층과 상호 작용하기 위한 객체(ex. repository)

## - 디렉터리

### main

실제 코드 작성하는 공간.

### test

프로젝트의 소스 코드를 테스트할 목적의 코드나 리소스 파일 들어 있다.

### build.gradle

빌드를 설정하는 파일. 의존성이나 플러그인 설정 등과 같이 빌드에 필요한 설정을 할 때 사용.

### setting.gradle

빌드할 프로젝트의 정보를 설정하는 파일

## 테스트 코드

### given — when — then

- given: 테스트 실행 준비 단계
- when: 테스트 진행 단계
- then: 결과 검증 단계

### Junit

자바 언어를 위한 단위 테스트 프레임워크.

**[특징]**  
- 테스트 방식을 구분할 수 있는 애너테이션 제공  
- 예상 결과를 검증하는 어설션 메서드 제공  
- 사용 방법 단순. 테스트 코드 작성 시간이 적음  
- 자동 실행, 자체 결과를 확인하고 즉각적인 피드백 적용.

### [용어 설명]

단위 테스트: 작성한 코드가 의도대로 작동하는지 작은 단위로 검증하는 것. 보통 **메서드 단위**로 테스트한다.
