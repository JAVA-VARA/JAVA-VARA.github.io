## 4장 테스트

## Test 관련 Annotation

### @BeforeAll

전체 테스트를 시작하기 전 한 번만 실행된다. 전체 테스트 실행 주기에서 한 번만 호출되어야 하므로 static 메서드로 선언한다.

(ex)db연결, test 환경 초기화

### @BeforeEach

테스트 케이스를 시작하기 전 매번 실행된다. 각 인스턴스에 대해 메서드를 호출되어야 하므로 메서드는 static이 아니어야 한다.

(ex)테스트 메서드에서 사용하는 객체 초기화, 테스트에 필요한 값 미리 넣을 때 사용.

### @AfterAll

전체 테스트를 마치고 종료하기 전 한 번만 실행.전체 테스트 실행 주기에서 한 번만 호출되어야 하므로 static 메서드로 선언한다.

(ex)db 연결 종료, 공통적으로 사용하는 자원 해제

### @AfterEach

테스트 케이스를 종료하기 전 매번 실행된다.

(ex)테스트 이후 특정 데이터 삭제 해야하는 경우

```
import org.aspectj.lang.annotation.After;
import org.junit.jupiter.api.*;

public class JUnitCycleTest {
    @BeforeAll
    static void beforeAll(){
        System.out.println("@BeforeAll");
    }

    @BeforeEach
    public void beforeEach(){
        System.out.println("@BeforeEach");
    }

    @Test
    public void test1(){
        System.out.println("Test1");
    }
    @Test
    public void test2(){
        System.out.println("Test12");
    }

    @Test
    public void test3(){
        System.out.println("Test13");
    }

    @AfterAll
    static void afterAll(){
        System.out.println("@AfterAll");
    }

    @AfterEach
    public void afterEach(){
        System.out.println(("@AfterEach"));
    }
}

```

### @SpringBootTest

메인 애플리케이션 클래스에 추가하는 애너테이션인 SpringBootApplication이 있는 클래스를 찾고,   
그 클래스에 포함되어 있는 빈을 찾은 다음   
테스트용용 애플리케이션 컨택스트 라는 것을 만든다.

### @AutoConfigureMockMvc

MockMvc를 생성하고 자동으로 구성하는 애너테이션.

MockMvc은 어플리케이션을 서버에 배포하지 않고도 테스트용 MVC 환경을 만들어 요청 및 전송, 응답 기능을 제공하는 유틸리티 클래스이다.  
즉, 컨트롤러를 테스트할 대 사용되는 클래스이다.

### @BeforeEach

테스트 케이스를 시작하기 전 매번 실행된다. 여기서는 MockMvcSetUp()메서드를 실행해 MockMvc를 설정해준다.

### @AfterEach

테스트 케이스를 종료하기 전 매번 실행된다. 여기서는 CleanUp()메서드를 실행해 member 테이블에 있는 데이터들을 모두 삭제해준다.

```
package sjspring.shop.springbootdeveloper;

import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.ResultActions;
import org.springframework.test.web.servlet.setup.MockMvcBuilders;
import org.springframework.web.context.WebApplicationContext;
import sjspring.shop.springbootdeveloper.Member;
import sjspring.shop.springbootdeveloper.MemberRepository;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
class TestControllerTest {

    @Autowired
    protected MockMvc mockMvc;

    @Autowired
    private WebApplicationContext context;

    @Autowired
    private MemberRepository memberRepository;

    @BeforeEach
    public void mockMvcSetUp() {
        this.mockMvc = MockMvcBuilders.webAppContextSetup(context)
                .build();
    }

    @AfterEach
    public void cleanUp() {
        memberRepository.deleteAll();
    }

    @DisplayName("getAllMembers: 아티클 조회에 성공합니다.")
    @Test
    public void getAllMembers() throws Exception {
        // given
        final String url = "/test";
        Member savedMember = memberRepository.save(new Member(1L, "홍길동"));

        // when
        final ResultActions result = mockMvc.perform(get(url)
                .accept(MediaType.APPLICATION_JSON));

        // then
        result
                .andExpect(status().isOk())
                .andExpect(jsonPath("$[0].id").value(savedMember.getId()))
                .andExpect(jsonPath("$[0].name").value(savedMember.getName()));
    }
}
```

### 메소드

- **perform(): **요청 전송 역할. 결과로 ResultActions 객체를 받으며, ResultActions 객체는 반환값을 검증하고 확인하는 andExpect() 메서드를 제공해준다.
- **accept(): **무슨 타입으로 응답을 받을지 결정.
- **andExpect(): **응답 검증. TestController에서 만든 API는 응답으로 OK(200)을 반환하므로, 이에 해당하는 메서드인 isOk를 사용해 응답 코드가 OK(200)인지 확인합니다.
- **jsonPath(“$[0].${필드명}”):** JSON의 응답값의 값을 가져오는 역할. 0번째 배열에 들어있는 객체의 id, name값을 가져오고, 저장된 값과 같은지 확인한다.

### 응답 코드 및 코드 검증 매핑 메서드

200 OK | isOk() | 요청이 성공적으로 수행되었음.  
201 OK | isCrated() | 요청이 성공적으로 수행, 새로운 리소스 생성되었음.  
400 OK | isBadRequest() | 요청 값이 잘못되어 요청에 실패  
403 OK | isForbidden() | 권한이 없어 요청에 실패  
404 OK | isNotFound() | 요청 값으로 찾은 리소스가 없어 요청에 실패  
4xx OK | is4xxClientError() |   
500 OK | isinternalServerError() | 서버 상에 문제가 있어서 요청에 실패  
5xx OK | is5xxClientError() |

## 5장 ORM

객체와 데이터베이스를 연결해 자바 언어로만 데이터베이스를 다룰 수 있게 하는 도구.

- H2: 스프링부트가 지원하는 인메모리 RDBMS. 애플리케이션 내부에 데이터를 저장한다. 그래서 애플리케이션을 다시 실행하면 데이터는 초기화된다.  
개발 시 테스트 용도로 간편하게 사용되며, 실제 서비스에는 사용되지 않는다.

### JPA와 Hibernate

- JPA(Java Persistence API): 자바 객체와 DB를 연결해 Data를 관리한다. 객체 지향 도메인 모델과 DB의 다리 역할을 한다.
- Hibernate: Java용 ORM 프레임워크. 자바 객체를 통해 DB 종류에ㅐ 상관없이 DB를 자유롭게 사용할 수 있게 한다.   
JPA의 인터페이스를 구현한다. 내부적으로는 JDBC API를 사용한다.

### Entity

DB의 테이블과 매핑되는 객체. 본질적으로는 자바의 일반 객체와 같으나, DB의 테이블과 직접 연결된다는 특징이 있다.

### Entity Manager

Entity를 관리해 DB와 Application 사이에서 객체를 생성, 수정, 삭제하는 등의 역할을 한다.

ex) 회원1, 회원2 동시에 회원 가입 요청.

회원1의 요청에 대해 **→** 엔티티 매니저 팩토리에서 가입 처리할 엔티티 매니저를 생성 **→ **생성된 Entity 매니저가 DB에 가입 요청한 회원의 정보 저장 **→ **회원2 요청 동일하게 처리 **→ **Entity 매니저는 필요한 시점에 DB와 연결한 뒤에 쿼리한다.

### Entity Manager Factory

Entity Manager를 만드는 곳. IOC에 **하나만 생성되어 관리**되고 있어 동시성에 문제가 생길 수 있다. 그래서 실제로 Entity Manager가 아닌 실제 Entity Manager와 연결하는 프록시 Entity Manager를 사용하고, 필요할 때 db transaction과 관련된 실제 Entity Manager를 호출한다.

### 영속성 컨텍스트

Entity를 관리하는 가상 공간.

[기능]  
공통: DB 접근을 최소화하여 성능을 높인다.

- **1차 캐시**  
영속성 컨텍스트는 내부에 1차 캐시를 가지고 있다. entity를 조회하면 1차 캐시에서 조회 후 있으면 값 반환, 없으면 db조회 후 1차 캐시에 저장 후 반환. 캐시된 데이터를 조회할 대는 db를 거치지 않아도 되므로, db를 빠르게 조회할 수 있다.

- **쓰기 지연**  
쿼리를 모아두었다가 transaction을 하면 한꺼번에 쿼리를 전송하여 DB System의 부담을 줄인다.

- **변경 감지**  
transaction 커밋 후 1차 캐시에 저장되어 있던 entity값과 현재 entity값을 비교하여 변경된 값을 db에 자동으로 반영한다.

- **지연 로딩**  
쿼리로 요청한 data를 바로 로딩하는 것이 아니라, 필요할 때 쿼리를 날려 데이터를 조회하는 것

### Entity의 상태

1. 분리상태: 영속성 컨텍스트가 관리하고 있지 않는 상태
2. 관리 상태: 영속성 컨텍스트가 관리하고 있는 상태
3. 비영속 상태: 영속성 컨텍스트와 관계없는 경우
4. 삭제된 상태

```
import jakarta.persistence.EntityManager;
import org.springframework.beans.factory.annotation.Autowired;
import sjspring.shop.springbootdeveloper.Member;

import javax.swing.text.html.parser.Entity;

public class EntityManagerTest {

    @Autowired
    EntityManager em;
    
    public void example(){
        // 1. 비영속 상태
        Member member = new Member(1L, "퐁길동");
        
        // 2. 관리 상태
        em.persist(member);
        
        //3. 분리 상태
        em.detach(member);
        
        //4. 삭제
        em.remove(member);
    }
}
```

### 자동키 생성 설정 방식

- AUTO(기본 값)
- IDENTITY: 기본 키 생성을 DB에 위임(=Auto_Increment)
- SEQUENCE: DB 시퀀스를 사용해서 기본 키를 할당하는 방법.
- TABLE: 키 생성 테이블 사용

Column 애너테이션의 속성

- name
- nullable
- unique

```
package sjspring.shop.springbootdeveloper.domain;

import jakarta.persistence.*;
import lombok.Builder;
import org.apache.catalina.mbeans.SparseUserDatabaseMBean;

@Entity
public class Article {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id", updatable = false)
    private Long id;
    
    @Column(name = "title", nullable = false)
    private  String title;
    
    @Column(name = "content", nullable = false)
    private String content;
    
    @Builder
    // 롬복에서 지원하는 애너테이션. 생성자 위에 입력하면 빌더 패턴 방식으로 객체 생성 가능하다.
    public Article(String title, String content){
        this.title = title;
        this.content = content;
    }
    protected Article(){
        public Long getId(){
            return id;
        }
        public String getTitle(){
            return title;
        }
        public String getContent(){
            return content;
        }
    }
    
}
```
