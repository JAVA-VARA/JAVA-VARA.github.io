3주전 커뮤니티에 내가 만든 서비스를 홍보했다. 글을 본 230명 중 **몇 명인지는 모르겠지만*** 총 44번 퀴즈가 수행되었다. (*\ㅇ/* 만세)

![](/images/medium/d96f103cf4f8/1.png)

## 불만을 토로하는 사용자들

사용자가 불편을 느낀 부분들을 댓글이나 퀴리로 받았다.

![](/images/medium/d96f103cf4f8/2.png)

![](/images/medium/d96f103cf4f8/3.png)

## 문제점

아래와 같이 3가지로 요약할 수 있겠다.

### 1. 화질

**[원인]**  
다음 스포츠에서 가져오는 선수 사진 원본의 퀄리티(화질)이 떨어진다

**[해결 방법]**  
- 다른 웹 사이트에서 선수 사진을 가져온다.  
- 용량이 높은 경우 리사이징 해보는 것도 고려해본다.

**[더 고민해봐야할 점]**  
`player` 엔티티를 `playerInfo` 엔티티와 `playerPicture` 엔티티로 나누자. 이렇게 하면 대규모 데이터를 저장하기 쉽고, 이미지만 따로 관리하면서 리사이징하기 용이할 것으로 기대된다.

### 2. 문제 중복 출제

**[원인]**  
크롤링할 때 데이터가 중복으로 들어간 선수가 있었다.

- 평균적으로 팀당 선수단은 25명
- SQL 명령어로 10명의 선수를 랜덤으로 가져올 때, 중복된 선수가 있는 경우 중복으로 값을 가져올 확률이 매우 크다.

**[해결 방법]**  
SQL로 `PLAYER`를 받아올 때 `SET`으로 받아와 중복되는 값을 제거한다.

**[더 고민해봐야할 점]**  
크롤링할 때 데이터 수집이 누락되거나 중복으로 들어오는 경우는 예외 처리를 어떻게 할 것인지 고민해보기.

### 3. 복수 정답 처리

**[원인]**  
외국인 선수들을 한국어로 번역하면서 웹사이트마다, 사람마다 표기하는 방법이 다르다.

**[해결 방법]**  
1. 여러 웹사이트를 크롤링하여 선수들의 이름을 수집해 복수 정답이 가능하도록 한다.  
2. 어떤 웹사이트를 기준으로 선수 이름을 정답 처리하는지 사용자에게 공지한다.

**[더 고민해봐야할 점]  
**하나의 웹사이트만을 기준으로 했을 때 내가 설정한 정답과 사용자가 생각한 정답의 괴리가 크지만 모든 웹사이트를 전부 크롤링할 수 없다.

=>1번과 2번 방법을 모두 사용하여 유명하고 사용자가 많은 웹사이트를 추려 선수 이름을 크롤링한 후, 공지를 한다.

> **“정답은 ■■■, ●●●, ★★★ 기준이며, 그 외 정답은 오답 처리됩니다.”**

### [번외] 사용자가 몇 명인지 모른다.

**[문제 상황]  
**44번의 퀴즈가 수행되었지만, 몇 명의 사용자가 사용했는지 모른다. 1명이 여러 번 했는지, 여러 명의 사용자가 1번씩만 이용하고 재미없어서 그만두었는지 파악이 안 된다.

**[해결 방법]  
**게임을 시작하기 전 간단한 사용자 정보를 받거나, 회원 가입 혹은 IP 주소를 수집하는 등 어떤 방법을 사용할지 고민해봐야겠다.

## [결론]

앞으로 문제들을 하나씩 해결해나가는 과정을 기록고 서비스를 좀 더 나은 방향으로 개선시켜 나가야 겠다.
