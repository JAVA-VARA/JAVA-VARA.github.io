## 변수

워크벤치를 재시작할 때까지 유지되지만, 종료하면 없어진다.

```
SET @변수이름 = 변수의 값;  -- >변수의 선언 및 값 대입
SELECT @변수이름 ; -- > 변수의 값 출력
```

- LIMIT에서는 변수를 사용할 수 없기 때문에 문법상 오류 발생.

```
SET @count = 3;
Select mem_name, height FROM member ORDER BY height; LIMIT @count; 

[ERROR CODE]
LIMIT @count Error Code: 1064. You have an error in your SQL syntax; 
check the manual that corresponds to your MySQL server version for the right syntax 
to use near 'LIMIT @count' at line 1 0.000 sec
```

- LIMIT에서의 변수 사용 및 CONCAT()함수를 이용한 문자열 병합.

```
PREPARE mySQL FROM 'SELECT mem_name, height FROM member ORDER BY height LIMIT?';
EXECUTE mySQL USING @count;
```

1. count에 변수 3 대입
2. PREPARE는 ‘SELECT~LIMIT?’문을 실행하지 않고 mySQL이라는 이름으로 준비만 해놓는다. LIMIT 다음에 물음표는 현재는 모르지만 나중에 채워진다는 뜻
3. EXECUTE mySQL USING [@count](http://twitter.com/count); => USING으로 물음표에 [@count](http://twitter.com/count) 값을 대입하는 것.

```
-- 동일한 수식
Select mem_name, height FROM member ORDER BY height; LIMIT 3
```

## 변환

### 함수를 이용한 명시적 변환

```
SELECT AVG(price) AS '평균 가격' FROM buy; -- 평균 가격 '실수' 로 표현
SELECT CAST(AVG(price) AS SIGNED) '평균 가격' FROM buy;
SELECT CONVERT(AVG(price), UNSIGNED) '평균 가격' FROM buy;

-- CAST, CONVERT 함수 안에 올 수 있는 데이터 형식
-- CHAR, SIGNED(부호가 있는 정수 = INTEGER), 
-- UNSIGNED(부호가 없는 정수 = UNINTEGER), DATE, TIME, DATETIME 등이 있다. 

-- DATE 형식 변경
SELECT CAST('2022$12$12' AS DATE);
SELECT CAST('2022/12/12' AS DATE);
SELECT CAST('2022%12%12' AS DATE);
SELECT CAST('2022@12@12' AS DATE);

-- pirce와 amount를 곱한 실제 구매액을 표시
SELECT num, CONCAT(CAST(price AS CHAR), 'X', CAST(amount AS CHAR), '=') AS '가격X수량', price*amount AS '구매액' FROM buy; 
-- 가격, 수량 정수 => 문자로 변환. CONCAT()을 이용하여 문자를 이어줌.
```

### 암시적 변환

CAST()나 CONCAT()을 사용하지않고 자연스럽게 형이 변환되는 것.

```
SELECT '100' + '200'; -- 300
SELECT CONCAT('100' , '200'); -- 100200

SELECT 100 + '200'; -- 300
SELECT CONCAT(100 , '200'); -- 100200
```

## 조인

두개의 테이블을 서로 묶어서 하나의 결과를 만들어 내는 것.

### 내부 조인

**[1]일대다 관계**

- 정의:  
하나의 테이블에서는 하나의 값만 존재 해야 하지만, 연결된 다른 테이블에는 여러 개의 값이 존재할 수 있다. 주로 기본키(PK)와 외래키(FK) 관계로 맺어져 있어 PK-FK 관계라고 부르기도 한다.

- 조인하고자 하는 모든 테이블에 데이터가 있어야만 결과가 나온다.
- 형식

```
SELECT <열 목록>
FROM <첫 번째 테이블>
    INNER JOIN <두 번째 테이블>
    ON <조인될 조건>
[WHERE 검색 조건];
```

[예시]

1. buy 테이블에서 mem_id가 GRL 인 것을 추출( WHERE buy.mem_id = ‘GRL’)
2. GRL과 동일한 값을 member 테이블에서 검색  
(buy.mem_id = member.mem_id)

3. GRL 이라는 아이디를 찾은 후 buy 테이블과, member 테이블 결합(join)

```
USE market_db;
SELECT* 
FROM buy 
INNER JOIN member 
ON buy.mem_id = member.mem_id
WHERE buy.mem_id = 'GRL';
```

- error code 발생: 어느 테이블의 mem_id를 추출할지 정확하게 알지 못하여 발생

```
SELECT mem_id, mem_name, prod_name, addr, CONCAT(phone1, phone2) AS '연락처'
FROM buy
 INNER JOIN member
    ON buy.mem_id = member.mem_id;
```

=> 수정: mem_id를 어느 테이블에서 가져올지 명시해준다.(buy.mem_id) 더불어, 각 열의 정보를 어느 테이블에서 가져오는지 명시해준다.

```
SELECT buy.mem_id, member.mem_name, buy.prod_name, member.addr, CONCAT(member.phone1, member.phone2) AS '연락처'
FROM buy
 INNER JOIN member
    ON buy.mem_id = member.mem_id;
```

=> 테이블에 별칭을 붙여 간단하게 열을 불러와 조인할 수 있다.

```
SELECT B.mem_id, M.mem_name, B.prod_name, M.addr, CONCAT(M.phone1, M.phone2) AS '연락처'
FROM buy B  -- 테이블에 별칭을 붙일 수 있다
 INNER JOIN member M -- 테이블에 별칭을 붙일 수 있다. 
    ON B.mem_id = M.mem_id
    ORDER BY M.mem_id;
```

=> 중복된 결과를 1 삭제하고 싶은 경우, DISTINCT 사용

```
SELECT DISTINCT M.mem_id, M.mem_name, M.addr -- DISTRINT를 이용하여 중복된 정보 제거.
FROM buy B 
INNER JOIN member M 
ON B.mem_id = M.mem_id
ORDER BY M.mem_id;
```

### 외부 조인

두 테이블을 조인할 때 필요한 내용이 한쪽 테이블에만 있어도 결과를 추출할 수 있다.(한 쪽 테이블에만 데이터가 있어도 출력된다.)

```
SELECT <열 목록>
FROM <첫 번째 테이블(LEFT 테이블)>
    <LEFT | RIGHT | FULL> OUTER JOIN <두 번째 테이블(RIGHT 테이블)>
    ON <조인될 조건>
[WHERE 검색 조건];
```

[예시]

```
SELECT M.mem_id, M.mem_name, B.prod_name, M.addr
FROM member M  -- 왼쪽에 있는 회원 테이블을 기준으로 외부 조인한다.
 LEFT OUTER JOIN buy B
    ON M.mem_id = B.mem_id
    ORDER BY M.mem_id;
                      
                                ...


SELECT M.mem_id, M.mem_name, B.prod_name, M.addr
FROM buy B  -- 오른쪽에 있는 회원테이블을 기준으로 외부 조인한다.
 RIGHT OUTER JOIN member M
    ON M.mem_id = B.mem_id
    ORDER BY M.mem_id;
```

![](/images/medium/2c2031e45424/2.png)

=> buy 테이블에 없는(NULL값인) 데이터까지 조인된 테이블에 나오는 것을 확인할 수 있다.

=> 동일한 조건으로 INNER JOIN하는 경우 아래와 같이 두 테이블에 모두 데이터가 있는 경우만 결과가 나옴을 확인할 수 있다.

```
SELECT M.mem_id, M.mem_name, B.prod_name, M.addr
FROM buy B  
 inner JOIN member M
    ON M.mem_id = B.mem_id
    ORDER BY M.mem_id;
```

![](/images/medium/2c2031e45424/3.png)

- 물품을 한 번도 구매하지 않은 회원 검색

```
SELECT DISTINCT M.mem_id, B.prod_name, M.mem_name, M.addr
FROM member M
LEFT OUTER JOIN buy B
ON M.mem_id = B.mem_id
WHERE B.prod_name IS NULL
ORDER BY M.mem_id;
```

### 기타 조인(1) — 상호 조인

한쪽 테이블의 모든 행과 다른 쪽 테이블의 모든 행을 조인시키는 기능. 상호 조인 결과의 전체 행 개수는 두 테이블의 각 행의 개수를 곱한 수가 된다.

```
SELECT * 
FROM buy
CROSS JOIN member;
```

![](/images/medium/2c2031e45424/5.png)

- 특징
1. ON 구문을 사용할 수 없다.
2. 테스트용으로 대용량 데이터 생성할 때 주로 사용된다.

```
SELECT COUNT(*) "데이터 개수"
FROM sakila.inventory
CROSS JOIN world.city;
```

![](/images/medium/2c2031e45424/6.png)

### 기타 조인(2) — 자체 조인

자신이 자신과 조인. 1개의 테이블을 사용한다.   
테이블을 1개만 사용하므로 다른 별칭을 이용해 서로 다른 테이블처럼 사용한다.

```
SELECT <열 목록>
FROM <테이블> 별칭 A
    INNER JOIN <테이블> 별칭 B
    ON <조인될 조건>
[WHERE 검색 조건];
```

**[예시]**

```
SELECT A.emp AS "직원", B.emp AS "직속상관", B.phone AS "직속상관연락처"
FROM emp_table A
INNER JOIN emp_table B 
ON A.manager = B.emp
WHERE A.emp = '경리부장';
```
