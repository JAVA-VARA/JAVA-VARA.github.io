작업 현황을 보여 주는 로컬 허브에 세션 현황 페이지를 새로 붙인 뒤, 허브를 `pythonw` 로 다시 띄웠다.
그런데 세션 페이지만 열리지 않고 매번 연결이 끊겼다.

```
연결이 예기치 않게 닫힘
```

## [문제 상황]

콘솔 `python` 으로 띄우면 정상, `pythonw` 로 띄우면 세션 페이지(`/sessions/`, `data.json`) 요청이 매번 끊김.

## [원인]

`pythonw` 에서는 `sys.stderr` 가 None 인데, 요청 로그를 남기는 기본 `log_message` 가 `sys.stderr.write` 를 불러 응답 도중 AttributeError 가 난 문제.

## [해결]

1. 세션 페이지 `Handler` 의 `log_message` 를 `print` 로 덮어씀
2. `sys.stderr = None` 상태에서 실제 서버에 요청해 200 을 확인하는 회귀 테스트 추가

## [해결 과정]

## #pythonw

콘솔 `python` 과 `pythonw` 의 차이를 먼저 정리하면 아래 세 가지다.

1. `pythonw` 는 콘솔 창 없이 도는 실행 방식이다. 출력을 받을 콘솔이 없어서 `sys.stderr` 가 None 이 된다.
2. `http.server` 의 `BaseHTTPRequestHandler.log_message` 는 기본 구현이 요청마다 `sys.stderr.write` 를 부른다.
=> `pythonw` 에서는 None 에 `.write` 를 부르는 셈이라, 응답을 보내는 도중에 AttributeError 가 난다.
3. 그래서 콘솔 `python` 이나, stderr 를 파일로 돌린 `pythonw` 에서는 `sys.stderr` 가 살아 있어 정상이었다.

즉 서버 코드가 틀린 게 아니라, 로그를 쓸 곳이 없는 실행 환경에서 기본 로그 함수가 터진 것.

## #Heuristics

1. 서버 코드가 아니라 실행 방식의 차이에서 오는 문제일 것이다.
=> 같은 허브를 콘솔 `python` 으로 띄우거나, `pythonw` 로 띄우되 stderr 를 파일로 돌리면 정상이었다. `pythonw` 에서 stderr 가 비어 있을 때만 끊기는 것을 확인함.

2. 같은 허브 안에서 멀쩡한 페이지와 끊기는 페이지의 차이가 있을 것이다.
=> 결정 기록 페이지의 `Handler` 는 이미 `log_message` 를 `print` 로 덮어써 두어서 문제가 없었다. 새로 붙인 세션 페이지의 `Handler` 만 덮어쓰지 않아 기본 구현(`sys.stderr.write`)을 그대로 쓰고 있었다.

## #수정

- serve_sessions.py

```python
class Handler(BaseHTTPRequestHandler):
    def _send(self, code: int, body: bytes = b"", kind: str = "text/html") -> None:
        ...생략...

    def log_message(self, format: str, *args: Any) -> None:  # => 추가
        print(format % args)                                   # => 추가
```

## #테스트

`sys.stderr` 를 None 으로 바꾼 상태에서 실제 서버를 띄우고 `/` 와 `/data.json` 을 요청해 200 을 확인하는 테스트를 넣었다.

- test_sessions_status.py

```python
def test_handler_without_stderr(monkeypatch: pytest.MonkeyPatch) -> None:
    ...생략...
    monkeypatch.setattr(sys, "stderr", None)  # => pythonw 환경 흉내
    with ThreadingHTTPServer(("127.0.0.1", 0), serve_sessions.Handler) as server:
        ...생략...
            for path in ("/", "/data.json"):
                with urlopen(f"http://127.0.0.1:{server.server_port}{path}") as response:
                    assert response.status == 200
```

=> 테스트 14개 통과, 코드 리뷰(low) 지적 없음.

## [재발 방지]

- `sys.stderr = None` 상태에서 실제 요청이 200 으로 끝나는지 보는 회귀 테스트를 남겼다.

## [결론]

콘솔에서는 되고 `pythonw` 에서만 안 되면 코드보다 "출력할 곳이 있는가"를 먼저 의심해야 한다.
기본 구현이 어디에 쓰는지 모르고 넘어간 함수 하나가 응답 전체를 끊을 수 있다는 걸 알게 됐다.
`pythonw` 로 띄우는 서버는 로그 함수부터 덮어써 두는 습관을 들여야겠다.
