## 로깅

개발 시, 운용 시 예기치 않은 오류가 발생하는 경우, 앱에서 무슨 일이 발생하고 있는지 확인해야 할 필요성이 있을 때 로거 사용.

로거를 이용하여 애플리케이션 로그(앱의 동작, 상황)를 콘솔이나 파일에 출력할 수 있다.

### 로그 레벨:

지정한 로그 레벨보다 레벨이 높은 로그만 출력된다.

- CRITICAL(치명적 오류): 프로그램의 이상 종료 수반하는 것과 같은 오류
- ERROR: 실행오류
- WARNING:오류에 가까운 현상
- INFO: 정상 동작 확인에 필요한 정보
- DEBUG: 개발 시 필요한 정보

```
#로그 출력
import logging
```

```
myapp.logger.critical("fatal error")
myapp.logger.error("error")
myapp.logger.warning("warning")
myapp.logger.info("info")
myapp.logger.debug("debug")
```

약간의 좌절을 맛본 후 SMTP Server가 무엇인지 부터 확인해야겠다는 생각이 들어 관련 정보를 찾아보았다.

### SMTP(Simple Mail Transfer Protocol):

전자 메일 “***전송”***을위한 표준 프로토콜.

### SMTP 서버란:

SMTP 프로토콜을 사용해 이메일을 전송하고 수신할 수 있는 메일 서버.  
이메일 클라이언트는 이메일 전송을 시작할 수 있게 이메일 공급자의 SMTP 서버와 직접 연결한다.

- **메일 제출 에이전트(MSA):** MSA는 이메일 클라이언트로부터 이메일을 수신합니다.
- **메일 전송 에이전트(MTA):** MTA는 전달망의 다음 서버로 이메일을 전송합니다. 앞에서 설명한 대로 필요할 경우 수신자 도메인의 [메일 교환(MX) DNS 레코드](https://www.cloudflare.com/learning/dns/dns-records/dns-mx-record/)를 찾기 위해 DNS를 쿼리할 수 있습니다.
- **메일 전달 에이전트(MDA):** MDA는 MTA에서 이메일을 수신해서 수신자의 받은메일함에 보관합니다.

### 작동 방식

- 송신: sj.youns1027@gmail.com
- 수신: xxxx@naver.com(문의 폼 작성 user의 이메일 주소)
1. 보낸 사람 SMTP 메일 서버는 “gmail”서버이고 받는 사람 SMTP 메일 서버는 “naver”이다. 전자 메일 클라이언트(여기서는 gmail)는 전자 메일의 SMTP 메일 서버 (이 경우에는 Google 서버)에 로그인하는 것을 도와준다. 웹 브라우저를 통해 서버 웹 사이트에 로그인하고 메일을 보내고 받을 수 있다.
2. 문의 폼에 메일 주소를 입력 후 제출하면, 메일이 Gmail SMTP 서버에 도달하여 저장된다.
3. Gmail SMTP 서버는 받는 사람의 주소를 ID “xxxx”와 DNS “naver.com”의 두 부분으로 액세스한다. Gmail SMTP 서버는 수신자에 대한 정보를 얻기 위해 DNS 서버에 접속합니다.
4. DNS 서버는 우선 순위 정보를 사용하여 받는 사람의 도메인 이름에 매핑된 IP 주소를 반환한다. (받는 사람의 SMTP 서버의 IP 주소). 받는 사람이 여러 서버를 포함하면 여러 IP 주소가 우선 순위로 제공된다.
5. IP 주소를 받은 후 보낸 사람 SMTP 서버는 받는 사람 SMTP 서버를 찾을 때까지 IP 주소에 우선 순위를 부여합니다.
6. 받는 사람의 SMTP 서버로 메일이 전송됩니다.
7. 받는 사람 SMTP 서버는 받는 사람의 ID 즉 “xxxx”에 액세스하여 사용자의 계정에 저장한다.

### SMTP에서 사용하는 포트

포트란? 네트워킹에서 [포트](https://www.cloudflare.com/learning/network-layer/what-is-a-computer-port/)란 네트워크 데이터를 수신하는 가상 지점

- **포트 25**는 SMTP 서버 사이를 연결하는 데 가장 많이 사용됩니다. 스팸 발송자가 이 포트를 악용해 스팸을 대량 전송하려고 하므로, 현재는 최종 사용자 네트워크의 방화벽에서 이 포트를 차단할 때가 많습니다.
- 한때 **포트 465**는 [보안 소켓 계층(SSL)](https://www.cloudflare.com/learning/ssl/what-is-ssl/) 암호화와 함께 SMTP에 사용하도록 지정되었습니다. 하지만 SSL은 [Transport Layer Security(TLS)](https://www.cloudflare.com/learning/ssl/transport-layer-security-tls/)으로 대체되어, 최신 이메일 시스템에서는 이 포트를 사용하지 않습니다. 레거시(이전) 시스템에서만 나타납니다.
- 이제 **포트 587**이 이메일 제출용 기본 포트입니다. 이 포트를 통과하는 SMTP 통신은 TLS 암호화를 이용합니다.
- **포트 2525**는 SMTP와 공식적으로 연결되어 있지는 않지만, 일부 이메일 서비스에서는 앞서 언급한 포트가 차단되었을 경우 이 포트로 SMTP 전송이 제공됩니다

(출처:[https://www.cloudflare.com/ko-kr/learning/email-security/what-is-smtp/](https://www.cloudflare.com/ko-kr/learning/email-security/what-is-smtp/))

SMTP 가 작동 방식을 확인 후 지금까지 엄청난 뻘짓(?)을 하고 있었음을 깨달았다. 송부인 혹은 수신인의 메일주소를 SMTP 서버가 읽을 수만 있게 해주면 되는 것 같아, 아래와 같이 다시 문제 해결을 진행했다.

## [Bouns] 프로그래머스 예제

문자열에 따라 다음과 같이 두 수의 크기를 비교하려고 합니다.

- 두 수가 `n`과 `m`이라면
- “>”, “=” : `n` >= `m`
- “<”, “=” : `n` <= `m`
- “>”, “!” : `n` > `m`
- “<”, “!” : `n` < `m`

두 문자열 `ineq`와 `eq`가 주어집니다. `ineq`는 "<"와 ">"중 하나고, `eq`는 "="와 "!"중 하나입니다. 그리고 두 정수 `n`과 `m`이 주어질 때, `n`과 `m`이 `ineq`와 `eq`의 조건에 맞으면 1을 아니면 0을 return하도록 solution 함수를 완성해주세요.

[sol1]

```
def solution(ineq, eq, n, m):
    if ineq + eq == "<=":
        x = n <= m
    elif ineq + eq == ">=":
        x = n <= m
    elif ineq + eq == ">!":
        x = n > m
    elif ineq + eq == "<!":
        x = n < m

    if x == True:
        return 1
    else:
        return 0
```

[sol2]

```
def solution(ineq, eq, n, m):
    if ineq == "<":
        if eq == "=":
            answer = n <= m
        else:
            answer = n < m

    if ineq == ">":
        if eq == "=":
            answer = n >= m
        else:
            answer = n > m

    return 1 if answer == True else 0
```

[sol3]dictionary의 key,value를 이용하여 더 간결하게 코드를 작성해보았다.

```
def solution3(ineq, eq, n, m):
    BigSmall = {
        ">=": n >= m, 
        "<=": n <= m, 
        ">!": n > m, 
        "<!": n < m}
    answer = BigSmall[ineq + eq]

    return 1 if answer == True else 0
```
