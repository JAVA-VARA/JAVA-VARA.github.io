## 오버라이딩

## 클래스 형변환

Car 부모

```
package test;

public class Car {
    public void run() {
        System.out.println("Car의 run 메서드");
    }
}
```

Van 자식

```
package test;

public class Van extends Car {
    public void ppangppang() {
        System.out.println("빵빵");
    }
}
```

상속 관계가 성립되므로, Van 객체를 Car형의 참조 변수로 참조할 수 있다.

```
package test;

public class VanExam {
    public static void main(String[] args) {
        Car c = new Van();
        c.run();
    }
}
```

=> Car c = new Van(); Car형의 변수 c가 Van의 인스턴스를 가리키고 있다. 묵시적 형변환이 일어난 것(큰 그릇 -> 작은 그릇)

부모 타입으로 자식을 가리킬 수는 있지만 부모 타입으로 자식을 가리킨 경우, 부모가 가진 메서드만 사용할 수 있다.

```
package test;

public class VanExam {
    public static void main(String[] args) {
        // Van van = new Van();
        // van.run();
        Car c = new Van();
        c.run();
        // c.ppangppang(); //Van이 가진 메서드는 사용할 수 없다.
    }
}
```

### 형변환

```
package test;

public class VanExam {
    public static void main(String[] args) {
        // Van van = new Van();
        // van.run();
        Car c = new Van();
        c.run();
        // c.ppangppang();

        // Van van = c; => c는 Car형이기 때문에 Van형이 가리킬 수 없다.
        Van van = (Van) c; //명시적 형변환을 해준다.
        van.run();
        van.ppangppang(); //Van형의 메서드도 사용이 가능해진다.
    }
}
```

### 인터페이스의 default 메서드

1. 인터페이스를 default 키워드로 선언하면 메서드를 구현할 수 있다.
2. 구현한 클래스에서 default 메서드를 오버라이딩 할 수 있다.
3. default 메서드를 사용하는 이유  
인터페이스를 구현하는 모든 클래스는 인터페이스 내 모든 메서드를 구현해야한다. 만약 인터페이스를 변경해야 하는 경우, 인터페이스를 구현했던 모든 클래스가 변경 사항을 반영해야 한다. 이런 문제를 해결하기 위해 인터페이스에서 메서드를 구현할 수 있도록 default 기능이 추가되었다.

- 인터페이스

```
package test;

public interface Calculator {
    public int plus(int i, int j);

    public int multiple(int i, int j);
    //default 키워드를 이용한 인터페이스에 메서드 구현
    default int exec(int i, int j) {
        return i + j;
    }
    //static 키워드를 이용하여 인터페이스에 메서드를 구현할 수 있다.
    public static int exec2(int i, int j) {
        return i * j;
    
    }
}
```

- 인터페이스 기능 추가

```
package test;

public class MyCal implements Calculator {

    @Override
    public int plus(int i, int j) {

```


### 내부 클래스

클래스 안에 선언한 클래스. 특정 클래스 내에서만 사용하는 클래스를 내부 클래스로 선언한다. 선언하는 위치에 따라 네 가지 형태로 나뉜다.

### - instance class

```
public class InnerExam1 {
    // Cal 이라는 내부 class 선언
    class Cal {
        // #1 필드선언
        int value = 0;

        // #2 메서드 정의
        public void plus() {
            value++;
        }
    }

    // class Cal을 사용하기 위해서는 외부 class InnerExam1이 먼저 만들어져야 한다.
    public static void main(String[] args) {
        InnerExam1 t = new InnerExam1(); // #1 InnerExam1 선언
        t.new Cal(); // #2 Cal 객체 생성

        // #3 Cal 객체를 사용하기 위해서는 인스턴스 변수 선언해야 한다.
        InnerExam1.Cal cal = t.new Cal();
        // 바깥쪽 클래스 타입.내부클래스 타입

        cal.plus();
        System.out.println(cal.value);

    }
}
```

### - static class

InnerExam2에 객체를 생성할 필요 없이 바로 접근하여 사용 가능하다.

```
public class InnerExam2 {
public class InnerExam2 {
    static class Cal {
        int value = 0;

        public void plus() {
            value++;
        }
    }

    public static void main(String[] args) {
        InnerExam2.Cal cal = new InnerExam2.Cal();
        cal.plus();
        System.out.println(cal.value);

    }
}
```

### - local class

내부 클래스를 메서드 안에 선언하는 경우. 클래스를 메서드 안에서 지역 변수처럼 사용 가능하다.

```
public class InnerExam3 {
    public void exec() {// 메서드 만듬
        class Cal {
            int value = 0;

            public void plus() {
                value++;
            }
        }
        Cal cal = new Cal(); //메서드 안에서 Cal 객체를 생성
        cal.plus(); //메서드 안에서 Cal 객체 메서드 호출
        System.out.println(cal.value); //Cal 가진 value 호출
    }

    public static void main(String[] args) {
        InnerExam3 t = new InnerExam3();
        t.exec();

    }
}
```

### - anonymous class

클래스 정의와 동시에 객체를 생성하는 것. 자식 클래스를 만들 필요가 없는 경우 사용.

```
래퍼런스 변수.메서드명()
```

추상 클래스를 사용하기 위해서는 항상 추상 클래스를 상속받은 자식 클래스를 생성하고 사용해야한다.

그런데 추상클래스를 한 번만 사용하는 경우, 클래스를 따로 정의하고 사용하는 번거로움을 줄이기 위해 클래스 정의와 동시에 객체를 생성하는 익명 클래스를 사용한다.

```
public class ActionExam {
    public static void main(String[] args) {
        // Action action = new MyAction();
        // action.exec();
        Action action = new Action() {
        /*
        중괄호 안에 필요한 부분을 구현한다.
        이렇게 하면 Action 클래스를 상속받은 이름 없는 객체를 만든다는 의미.
        추상메서드를 오버라이드하거나, 메서드를 추가할 수 있다. 
        */
            @Override

                System.out.println("EXEC");
            }
        };

}
```

위 경우와 같이 , Action을 상속받는 클래스를 ActionExam클래스 안에서만 사용하고, 다른 클래스에서는 전혀 사용하지 않는 경우 한 번만 사용되므로, MyAction(자식 클래스)를 만들 필요가 없다.

## 예외 처리

### Exception

실행 시점에서 잘못된 값으로 발생하거나, 그 외 여러 상황*에서 발생하는 예기치 못한 사건.

*레퍼런스 변수를 사용하는 시점에서 해당 변수가 null값을 가지거나, 숫자값이 들어와야 하는데 문자 값이 들어온 경우 등이 있다.

예외 사항을 미리 예측하고 처리하는 것을 ‘예외 처리’ 라고 한다.

```
try{
    수행할 코드, 예외 발생 가능성이 있는 블록
}catch(발생할 수 있는 예외 타입 변수명){
    예외 처리 블록
}finally{
    예외 발생 여부와 상관없이 무조건 실행하는 블록(생략 가능)
}
```

[예외 처리 flow]

try 블록에서 예외가 발생 → 발생한 지점부터 try 블록 마지막까지는 실행 불가능 → catch 블록으로 넘어온다. → catch 블록에서 선언한 예외와, 발생한 예외가 일치할 때 catch 블록을 실행 → 예외 발생 여부와 상관없이 finally 블록 실행.

- 예외 발생으로 인한 error 발생

```
public class ExceptionExam {
    public static void main(String[] args) {
        int i = 10;
        int j = 0;
        int k = i / j;
        System.out.println(k);
    }
}

[실행 결과]
Exception in thread "main" java.lang.ArithmeticException: / 
by zero at ExceptionExam.main(ExceptionExam.java:5)
```

- try — catch — finally 구문 실행

```
public class ExceptionExam {
    public static void main(String[] args) {
        int i = 10;
        int j = 0;
        try {
            int k = i / j;
            System.out.println(k);
        } catch (ArithmeticException e) {
            System.out.println("0으로 나눌수 없습니다." + e.toString());
        } finally {
            System.out.println("예외와 상관없이 무조건 실행");
        }

        System.out.println("main end!!");
    }
}

[실행 결과]
0으로 나눌수 없습니다.java.lang.ArithmeticException: / by zero
예외와 상관없이 무조건 실행
main end!!
```

모든 예외 객체는 Exception클래스를 상속받는다. catch 블록의 발생 가능 예외 클래스에 Exception이라고 작성하면 어떤 예외가 발생하더라도 하나의 catch 블록으로 처리할 수 있다.

*toString()메서드: 예외정보를 알려준다.

```
catch(Exception e){
    System.out.println("예뵈 발생" + e.toString());
}
```

### Exception 발생시키기

throw 키워드를 통해 강제로 오류를 발생시킨다.

```
public class ExceptionExam5 {
    public static void main(String[] args) {

        int i = 10;
        int j = 0;
        try {
            int k = divide(i, j);
            System.out.println(k);
        } catch (IllegalArgumentException e) {
            System.out.println(e.toString());

        }

    }

    public static int divide(int i, int j) throws IllegalArgumentException {
        if (j == 0) {
            throw new IllegalArgumentException("0으로 나눌 수 없습니다.");
        }
        int k = i / j;
        return k;
    }
}
[실행 결과]
java.lang.IllegalArgumentException: 0으로 나눌 수 없습니다.
```

### 사용자 정의 Exception

사용자는 Exception이나 runtimeException 클래스를 상속받아 새로운 Exception 클래스를 만들 수 있다. 새로운 클래스를 만든는 이유는 이름 때문.

클래스명을 보고 어떤 오류가 발생했는지 사용자에게 직관적으로 알려주기 위함.

```
public class 클래스명 extends Exception{...}
```

**— Checked Exception:** Exception을 상속받은 클래스. 에러 처리를 하지 않으면 컴파일 에러가 발생하기 때문에 반드시 에러 처리를 해야한다.

**— RuntimException:** RuntimException을 상속받아 정의한 Exception은 에러 처리를 하지 않아도 컴파일 에러를 발생시키지 않는다.

- Exception 객체 생성 후 생성자를 지정한다.

```
public class BizException extends RuntimeException {
    //어떤 에러가 발생했는지 string 값으로 메시지를 가져오는 생성자
    public BizException(String msg) {
        //메세지를 가져온 후 super()에 메세지를 보낸다.
        super(msg); 
    }
    //Exception을 받아들여 부모 생성자에게 넘겨주는 생성자
    public BizException(Exception ex) {
        super(ex);
    }
}
```

- Exception 발생 시 throws를 사용해 BizException을 넘겨준다.

```
public class BizService {
    public void bizMethod(int i) throws BizException {
        System.out.println("비즈니스 메서드 시작");

        if (i < 0)
            throw new BizException("매개변수 i는 0 이상 이어야 합니다.");
        System.out.println("비즈니스 메서드 종료");
    }

}
```

— if가 0보다 작은 경우 Exception이 발생하는데, 이 때 String으로 매개변수를 받아들일 수 있다.   
Exception의 메시지("매개변수 i는 0 이상 이어야 합니다.”)를 BizException에 전달한다.

- 사용자 정의 Exception 실행

```
public class BizExam {
    public static void main(String[] args) {
        BizService biz = new BizService();
        biz.bizMethod(5);
        try {
            biz.bizMethod(-3);

        } catch (Exception e) {
            e.printStackTrace();
        }

        System.out.println("프로그램종료");
    }
}
```

#1 -3 값을 인자로 가진 두번 째 메서드 호출  
#2 인자로 들어온 값이 0 보다 작음  
#3 BizException 발생  
#4 BizException thorws 함.  
#5 try — catch 문을 통해 예외 처리  
#6 예외 처리 후 끝까지 수행

- **Checked Exception과 Unchecked Exception의 차이점: **  
컴파일 시 컴파일 에러를 미리 발생시켜서 반드시 예외를 처리할 것인지 여부.
