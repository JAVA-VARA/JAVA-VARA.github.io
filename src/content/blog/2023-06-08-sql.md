## SQL 프로그래밍

SQL 프로그래밍은 기본적으로 스토어드 프로시저 안에서 만든다.

- **스토어드 프로시저 구조**

```
DELIMITTER $$
CREATE PROCEDURE 스토어드_프로시저_이름()
BEGIN
    -- SQL 프로그래밍 코딩
END $$  -- 스토어드 프로시저 종료
DELIMITTER;
```

```
CALL 스토어드_프로시저_이름();  -- 스토어드 프로시저 실행
```

### IF문(1)

- 기본 형식

```
IF <조건식> THEN
    SQL 코딩
END IF;
```

두 문장 이상인 경우 BEGIN~END로 묶어줘야 한다.

```
DROP PROCEDURE IF EXISTS ifPROC1; -- 기존에 ifProc1 이 있는 경우 삭제
DELIMITER $$ 
CREATE PROCEDURE ifProc1() -- 스토어드 프로시저의 이름을 ifProc()로 지정
BEGIN
IF 100 = 100 THEN -- 조건식 작성 => true인 경우 아래 행이 실행된다.
SELECT '100은 100과 같습니다.';
END IF;
END$$
DELIMITER ;
CALL ifProc1; -- CALL로 호출하면 ifProc()문 실행된다.
```

### IF~ELSE 문

```
DROP PROCEDURE IF EXISTS ifPROC2;
DELIMITER $$ 
CREATE PROCEDURE ifProc2()

DECLARE myNum INT;

IF myNum = 100 THEN
SELECT '100입니다.' ;
ELSE
SELECT '100이 아입니다.' ;
END IF;
END$$
DELIMITER ;
CALL ifProc2; 
```

### CASE 문

```
CASE
    WHEN 조건 1 THEN
        SQL 코드
    WHEN 조건 2 THEN
        SQL 코드
    ...
    ELSE
        SQL 코드
END CASE;
```

WHEN 다음에 조건이 나오며, 조건에 해당하지 않으면 마지막 ELSE문을 수행한다.

[예시1]

```
DROP PROCEDURE IF EXISTS casePorc;

DELIMITER $$

CREATE PROCEDURE caseProc()

BEGIN
DECLARE point INT;
DECLARE CREDIT char(1);
SET point = 88;

CASE
WHEN point >= 90 THEN
SET credit = 'A';
WHEN point >= 80 THEN
SET credit = 'B';
WHEN point >= 70 THEN
SET credit = 'C';
WHEN point >= 60 THEN
SET credit = 'D';
ELSE
SET credit = 'F';

END CASE;
SELECT CONCAT('취득점수==>', point), CONCAT('학점 ==>' , credit);
END $$
DELIMITER ;
CALL caseProc();
```

### WHILE 문

```
WHILE <조건식> DO
    SQL 코드
END WHILE;
```

[예시1]

```
DROP PROCEDURE IF EXISTS whileProc;

DELIMITER $$

CREATE PROCEDURE whileProc()
BEGIN
DECLARE i INT; -- 1~100까지 증가할 변수
DECLARE hap INT; -- 더한 값을 누적할 변수
SET i = 1;
SET hap = 0 ;

WHILE (i<= 100) DO
SET hap = hap + i;
SET i = i+1;
END WHILE;

SELECT '1부터 100까지의 합 ==>', hap;
END$$
DELIMITER ;
CALL whileProc();
```

[예시2]  
ITERATE 문은 CONTINUE,   
LEAVE문은 BREAK 와 유사한 기능을 한다.

```
DROP PROCEDURE IF EXISTS whileProc2;

DELIMITER $$

CREATE PROCEDURE whileProc2()
BEGIN
DECLARE i INT; -- 1~100까지 증가할 변수
DECLARE hap INT; -- 더한 값을 누적할 변수
SET i = 1;
SET hap = 0 ;

-- 
-- WHILE문을 myWhile이라는 레이블로 지정함.

myWhile: 
WHILE (i<= 100) DO
 IF(I%4) = 0 THEN
    SET i = i+1;
    ITERATE myWhile; -- 지정한 label 문으로 가서 반본문 진행
    END IF;
    SET hap = hap + i;
    IF(hap > 1000) THEN
  LEAVE myWhile; -- 지정한 label 문을 떠남(while문 종료)
 END IF;
    SET i = i+1;
END WHILE;

SELECT '1부터 100까지의 합(4의 배수 제외), 1000넘으면 바로 종료! ==>', hap;
END$$
DELIMITER ;
CALL whileProc2();
```

### 동적 SQL

- **PREPARE**  
SQL문을 실행하지 않고 미리 준비한다.

- **EXECUTE**  
준비한 SQL문을 실행한다.

- **DEALLLOCATE PREPARE myQuery;  
**실행 후 문장을 해제한다.

[예시1]

```
USE market_db;

PREPARE myQuery FROM 'SELECT*FROM member WHERE mem_id = "BLK"';
EXECUTE myQuery;
DEALLOCATE PREPARE myQuery;
```

[예시2]출입문에서 출입증을 태그하는 순간의 날짜와 시간이 insert되도록 하기

```
DROP TABLE IF EXISTS gate_table;
-- ID는 자동으로 증가되고, 출입하는 시간(entry_time)을 DATETIME 형식으로 지정
CREATE TABLE gate_table(id INT AUTO_INCREMENT PRIMARY KEY, entry_time DATETIME);

SET @curDate = CURRENT_TIMESTAMP(); -- 현재 날짜와 시간을 변수에 넣는다.

PREPARE myQuery FROM 'INSERT INTO gate_table VALUES(NULL,?)';
-- ?를 이용하여 entry_time 들어갈 값을 비워 놓는다.

EXECUTE myQuery USING @curDate;
-- USING 문을 이용하여 @curDate 변수를 넣은 후 실행한다.

DEALLOCATE PREPARE myQuery;

SELECT*FROM gate_table;
```

### 제약 조건

**[PRIMARY KEY 제약 조건]  
**중복될 수 없는 고유한 값, NULL 값 허용X

- ALTER TABLE에서 설정하는 기본 키 제약조건

```
ALTER TABLE member
    ADD CONSTRAINT
    PRIMARY KEY(mem_id);
```

```
CREATE TABLE member(

...생략...

CONSTRAINT PRIMARY KEY PK_member_mem_id(mem_id) -- 고유 키의 이름을 설정할 수 있다.

);
```

**[FOREIGN KEY 제약 조건]  
**두 테이블 사이의 관계를 연결해주고, 그 결과 데이터의 무결성을 보장해주는 역할을 한다. 외리 키가 설정된 열은 꼭 다른 테이블의 기본 키와 연결된다.

**기본 키**가 있는 테이블을 **기준 테이블**,  
**외래 키**가 있는 테이블을 **참조 테이블** 이라고 한다.

- **ON UPDATE CASECADE / ON DELETE CASCADE  
**기준 테이블의 데이터가 변경되거나 삭제되면, 참조 테이블의 데이터가 자동으로 변경/삭제되는 기능

```
CREATE TABLE buy(
num INT AUTO_INCREMENT NOT NULL PRIMARY KEY, -- PK 설정
mem_id CHAR(8) NOT NULL,
prod_name CHAR(6) NOT NULL,
);


ALTER TABLE buy
    ADD CONSTRAINT
    FOREIGN KEY(mem_id) REFERENCES member(mem_id) -- FK 설정
    ON UPDATE CASECADE
    ON DELETE CASCADE;
```

**[UNIQUE 제약 조건]  
**중복될 수 없는 고유한 값, NULL 값 허용 O

```
CREATE TABLE member -- 회원 테이블 생성
 (mem_id CHAR(8) NOT NULL PRIMARY KEY,
    ...생략...
  email CHAR(30) NULL, UNIQUE
  );
```

**[CHECK 제약 조건]  
**제약 조건에 위배되는 값 입력 시 오류 발생

**[예시1]**

```
CREATE TABLE member -- 회원 테이블 생성
 (mem_id CHAR(8) NOT NULL PRIMARY KEY,
  mem_name VARCHAR(10) NOT NULL,
    ...생략...   
  height TINYINT UNSIGNED NULL CHECK(height >= 100)
  );
```

**[예시2]  
**ALTER TABLE 문으로 제약 조건 추가  
IN() 안에 있는 값 중 하나와 같아야 참이 된다.

```
ALTER TABLE member
    ADD CONSTRAINT
    CHECK(phone1 IN('02', '031', '032', ... '061')
```

**[DEFAULT 정의]  
**입력하지 않았을 때, 자동으로 입력될 값 미리 지정.

```
CREATE TABLE member -- 회원 테이블 생성
 (mem_id CHAR(8) NOT NULL PRIMARY KEY,
  mem_name VARCHAR(10) NOT NULL,
    ...생략...   
  height TINYINT UNSIGNED DEFAULT 160
  );
```

## 뷰(가상 테이블)

데이터베이스 개체 중 하나. 데이터를 가지고 있지 않음. SELECT문으로 만들어져 있어, 접근하는 순간 SELECT문 실행되어 결과가 화면에 출력된다.

단순 뷰: 하나의 테이블과 연관된 뷰

복합 뷰: 2개 이상의 테이블과 연관된 뷰

- **뷰 생성**

```
CREATE VIEW 뷰_이름
AS
    SELECT 문;
```

- **뷰 접근**

```
SELECT 열_이름 FROM 뷰뷰_이름
WHERE 조건
```

- **뷰를 사용하는 이유**
1. 보안전체 테이블에서 원하는 정보만 SELECT하여 제공할 수 있다. 사용자마다 테이블에 접근하는 권한에 차별을 둘 수 있다.
2. 복잡한 SQL을 단순하게 만들 수 있다.

```
CREATE VIEW v_memberbuy
AS

    SELECT B.mem_id, M.mem_name, B.prod_name, M.addr, CONCAT(M.phone1, M.phone2) AS '연락처'
    FROM buy B  -- 테이블에 별칭을 붙일 수 있다
    INNER JOIN member M -- 테이블에 별칭을 붙일 수 있다. 
    ON B.mem_id = M.mem_id
    ORDER BY M.mem_id;
```

=> v_memberbuy를 테이블이라고 생각하고 간편하게 접근할 수 있다.

```
SELECT * FROM v_memberbuy WHERE mem_name = '블랙핑크';
```

- **뷰의 실제 작동**

[생성]

뷰에서 사용될 열 이름을 테이블과 다르게 지정 가능하며, 별칭을 사용하는 것과 동일하게 지정 가능하다.

중간에 띄어쓰기 가능하나 뷰 조회 시 열 이름에 공백이 있으면 백틱(`)으로 묶어줘야 한다.

## 인덱스

데이터를 빠르게 찾을 수 있도록 도와주는 도구

- **클러스터형 인덱스: **기본 키(Primary Key)로 지정하면 자동 생성. 테이블 당 1개만 생성 가능. 클러스터형 인덱스는 루트, 중간, 리프 페이지로 이루어져 있다.
- **보조 인덱스: **고유 키(Unique)로 지정하면 자동 생성. 여러 개를 만들 수 있으나, 자동 정렬 기능 없음. 데이터 페이지를 건드리지 않고 별도의 인덱스 페이지를 만든다. 데이터의 위치는 페이지 번호 +#위치로 기록된다.

### “익덱스”는 균형 트리* 구조로 만들어진다.

### 균형 트리*

- 노드: 데이터가 저장되는 공간, mySQL에서는 페이지라고 부른다. 페이지는 최소한의 저장 단위로 16Kbyte크기를 가진다.(=1건의 데이터만 입력해도 1개의 페이지 즉 16Kbyte가 필요하다.)
- 루트 노드: 가장 상위 노드
- 리프 노드: 제일 마지막에 존재하는 노드

=>균형 트리는 무조건 루트 페이지부터 검색한다. 효율성 판단은 몇 개의 페이지를 읽었느냐로 판단할 수 있다.

**인덱스**를 만들면 **SELECT의 속도는 향상**되나** 데이터 변경 작업(INSERT, UPDATE, DELETE) **시 **페이지 분할**이 일어나 **성능이 나빠진다.**

***페이지 분할:** 데이터를 입력할 때 입력할 페이지에 공간이 없어서 2개의 페이지로 데이터가 나눠지는 것.

### 인덱스 생성

PK or UNIQUE 지정 시 자동으로 인덱스가 생성된다.   
**직접 인덱스를 생성하려면 CREATE INDEX문 사용**(생성되는 인덱스는 보조 인덱스이다.)

[예시1]

```
CREATE INDEX idx_member_addr -- index의 이름
    ON member(addr); -- member 테이블의 주소(addr)을 단순 보조 인덱스로 설정

ANALYZE TABLE member; -- 인덱스 생성 후 ANALYZE TABLE 문을 사용해야 실제 적용된다.
```

=>단순 보조 인덱스: 중복을 허용하는 인덱스.

CREATE UNIQUE INDEX idx_member_mem_name -- index의 이름
    ON member(mem_name); -- mem_name를 고유 보조 인덱스로 설정
인덱스 제거

### 인덱스 제거

보조 인덱스를 먼저 제거. 클러스터형 인덱스 먼저 제거 시 데이터 재구성이 필요하여 효율성이 떨어진다.

```
DROP INDEX
```

PK or UNIQUE 지정 시 자동 생성된 인덱스는 제거 불가! ALTER TABLE로 고유키, 기본키 제거 후 인덱스를 제거할 수 있다.

```
ALTER TABLE member
    DROP PRIMARY KEY;

-- 에러 발생: 외래 키와 연결되어 있음. ->외래키 제거 후 기본 키 제거

ALTER TABLE buy
    DROP FOREIGN KEY buy_ibfk_1;
ALTER TABLE member
    DROP PRIMARY KEY;
```
