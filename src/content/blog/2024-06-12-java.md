### Test 진행 시 OutOfMemoryError를 마주한 후 Java 메모리 구조에 대해 자세히 알아보았다.

## JVM

운영 체제, CPU, 플랫폼에 상관 없이 어디에서나 가능하게 해주는 JVM.

### 자바 실행 과정

![](/images/medium/9624bd48b7b5/2.png)

- Class Loader: 컴파일러가 만든 클래스 파일을 JVM 내의 메모리 영역(Runtime Data Area)에 올리는 역할을 한다.
- Garbage Collector: 메모리 관리 기능을 자동으로 수행한다. 애플리케이션이 생성한 객체의 생존 여부를 판단하여 사용되지 않는 객체를 해제하는 방식으로 메모리를 관리한다.
- Execution Engine: Class Loader를 통해 JVM 내의 런타임 데이터 영역에 배치된 자바 바이트 코드를 명령어 단위로 읽어서 실행한다.
- Runtime Data Area: JVM 메모리 영역

### Runtime Data Area

JVM의 메모리 역역. 메소드 영역, 영역, 스택 영역, pc register, Native Method Area가 있다.

- **Method Area**: JVM에 의해 loading된 클래스들이 저장되며, 구현도니 메소드, 상수들이 저장된다.
- **Heap Area**: new 연산자로생선된 객체와 배열 저장. 주로 실행시간에 생성되는 객체를 저장하며 가비지 컬렉터에 의해 관리되는 역역이다.
- **Stack Area**: 수행되는 method 정보, 지역변수, 매개변수, 연산 중 발생하는 임시데이터 저장.  
method가 호출될 때마다 스택 프레임이 생성. 컴파일시 size 및 life cycle이 정해진다.

- **PC Register**: 연산 결과값을 메모리에 전달하기 전 저장하는 CPU 내의 기억 장치.  
현재 수행중인 JVM 명령 주소를 갖는다. 프로그램 실행은 CPU에서 Instruction을 수행한다. CPU는 Instruction을 수행하는 동안 필요한 정보를 CPU내 기억장치인 레지스터에 저장한다.

### 힙 영역

![](/images/medium/9624bd48b7b5/3.png)

- **Young Generation:** 새로운 객체를 할당하기 위해 확보된 공간  
**— Eden: **객체들이 최초로 생성되는 공간이며, new 연산자를 통해 생성된 객체가 위치하는 공간**  
 — From, To: **Eden에서 참조되는 객체가 Eden이 꽉찼을때 이동되는 공간

- **Old Generation:** 가비지 컬렉터가 사용하지 않는 객체들을 제거하고, Young Generation에 객체가 가득차면 Old Generation으로 이동된다.
- **Permanent Genteration**: 클래스와 메소드 메타 정보가 저장되는 공간, static변수와 static메소드가 저장되는 공간( java8부터 native 메모리로 이동, Metaspace 로 이름이 변경되었다.)

## Spring Test Run 시 OOM 발생

지금까지 JAVA 메모리 구조에 대해 공부했다. 다시 에러 메세지로 돌아가보면, 테스트를 진행할 때 Java heap space의 메모리가 부족해서 발생한 에러인 것을 알 수 있다.

![](/images/medium/9624bd48b7b5/1.png)

- **JVM 옵션 조정**

```
test {
  minHeapSize = "1g" // initial heap size
  maxHeapSize = "1g" // maximum heap size
}
```

![](/images/medium/9624bd48b7b5/6.png)

위의 옵션을 넣고 다시 테스트를 실행해보니다행히 OOM은 발생되지 않았지만 근본적인 해결책은 아니라는 생각이 들었다.

다음 에 test 진행 시 사용되는 메모리 사용량과, JVM의 default heap size를 확인해보고, 메모리 사용량이 급증한 원인을 찾아봐야겠다.
